# 绿风润耕智慧大棚总控 V4.2.1

## 1. 本版实际连接关系

> 虚拟大棚与能源系统 → 统一环境/能源状态 → Transformer 预测 → SAC 上层策略 → 约束控制与安全裁决 → 加热/通风口/保温帘/风机 → 功率平衡与设备实际效果 → 虚拟大棚反馈 → 前端总控

当前是单棚闭环演示，Transformer 和 SAC 已进入实际运行链路；GNN 是多棚协同扩展，不在本单棚版本中虚构节点关系。

## 2. 启动方式

确保 AI 环境位于 `C:\greenwind_ai_env`，然后双击：

```text
启动绿风润耕V4.bat
```

进入软件后点击右上角“启动虚拟大棚”。首次加载 Transformer 和 SAC 可能需要十几秒，状态变为 `RUNNING` 后即可操作。

如果无法启动，先双击 `验证绿风润耕整合版.bat`，保留错误窗口并按提示排查。

## 3. 五个页面分别做什么

- **大棚实况**：显示棚内东/中/西温度、湿度、CO₂、冠层温度、基质温度、基质含水率，以及室外温湿度、辐射和风速。总控曲线同时显示实测棚温、Transformer 未来 10/30 分钟预测和目标上下限。
- **控制中心**：切换人工、AI辅助、AI自动三种模式；直接调节加热、通风口、保温帘和风机；提供保温升温、通风降温、排湿和设备归零预设。
- **AI智能托管**：把专业模型输出翻译成可读建议，展示建议动作、安全裁决结果，并支持批准、修改或拒绝。
- **能源协同**：显示光伏/风电出力、市电功率、设备负荷、储能功率和 SOC；可手动模拟正常供电、限功率和停电，观察储能是否接管负荷。
- **实验与报告**：查看控制周期、人工命令、AI执行、安全裁决次数和温度趋势，打开运行记录目录。
- **系统与投运**：说明模型、状态文件、运行记录的位置，以及未来切换真实大棚时的接口边界。

## 4. 三种控制模式

| 模式 | 行为 |
|---|---|
| 人工控制 | 人工设定四类设备目标，系统仍会执行安全裁决 |
| AI建议 + 人工确认 | Transformer 与 SAC 形成建议，仿真暂停等待批准、修改或拒绝 |
| AI自动托管 | AI 每个周期自动执行，仍必须经过约束控制和安全裁决 |

人工按钮不是只改前端数字。命令会写入 `var\greenhouse_ui\commands`，统一运行层读取后作用到虚拟设备，虚拟大棚再按设备动作计算下一周期环境状态。

## 5. Transformer 曲线代表什么

- 绿色：当前周期虚拟传感器得到的中心棚温；
- 蓝色虚线：基于过去 60 分钟数据预测的未来 10 分钟棚温；
- 橙色虚线：预测的未来 30 分钟棚温；
- 灰色点线：当前生育阶段的目标温度上下限。

图上预测效果属于仿真环境验证。获得真实大棚数据后，应使用相同训练管线重新校准/微调，并重新计算独立测试集指标。

## 6. 最常修改的配置

文件：`config\ui_demo_config.json`

常用字段：

- `default_mode`：`manual`、`assist` 或 `auto`；
- `wall_interval_seconds`：每个控制周期在演示中等待多少秒；
- `assist_timeout_seconds`：AI辅助模式等待人工决定的秒数；
- `base_outdoor_temp_c`：仿真室外基础温度；
- `weather_scenes`：天气场景；
- `max_control_steps`：单次演示最大控制周期数。

模型路径已经配置完成，普通演示不需要修改 Python 文件。

## 7. 运行证据

运行结果位于：

```text
var\greenhouse_ui\
```

- `state.json`：前端读取的最新统一状态；
- `interaction_trace.csv`：每个控制周期的温度、预测、设备动作和安全裁决；
- `commands\`：尚未处理的前端命令；
- `command_archive\`：已处理命令，便于追溯。

## 8. 真实大棚接入边界

V4 可以证明预测、决策、约束、执行、反馈和人工复核在仿真环境中形成闭环，但不能表述为真实现场效果。真实接入需要新增传感器适配器与执行器适配器，保持同一字段和命令契约，并完成设备限值标定、断网/故障测试、Transformer 微调和现场分阶段试运行。

## 9. 热惯性模型与验证

V4.1 将棚内热过程统一为可配置的多热容网络。东、中、西三个空气分区、作物冠层、栽培基质与棚架/管路蓄热体都保存独立温度，各节点按能量平衡迭代：

```text
C_i × dT_i/dt = ΣQ_in - ΣQ_out
```

加热、太阳得热、覆盖散热、通风换热、相邻分区换热以及冠层、基质和棚架蓄放热共同决定下一时刻温度。因此设备开关不会直接把温度改成固定值。

在 AI 开发环境中运行：

```text
python tools\virtual_greenhouse\test_thermal_inertia.py
python tools\virtual_greenhouse\thermal_inertia_experiment.py
```

第一条命令执行 4 项回归测试；第二条生成加热开启—关闭阶跃响应的 CSV、JSON 指标和 PNG 曲线，输出位于 `tools\virtual_greenhouse\thermal_inertia_results\`。

当前热容和换热系数是用于系统研发的工程初值，阶跃实验证明热惯性机制已真正参与仿真计算，但不代表系数已经真实大棚标定。后续获得现场数据后，应使用加热启停、棚温、室外温度、风速与太阳辐射数据辨识这些参数。

## 10. 清洁能源与储能协同

V4.2 新增独立能源子系统。光伏和风电先供棚内设备，多余清洁能源用于充电；负荷高于设定阈值或市电限功率/停电时，储能在 SOC 安全边界内放电。若市电、清洁能源和电池仍无法满足负荷，能源系统会降低可供功率，并把有效设备功率反馈给热环境模型，而不是假定设备仍能满功率运行。

能源页面中的“市电正常、限功率供电、模拟市电停电、恢复场景时间表”都会进入真实仿真闭环。电池功率为正表示放电，为负表示充电。

V4.2.1 增加了市电按钮回执和选中状态。即使系统处于“AI建议＋人工确认”、环境仿真正在等待审核，市电切换也会作为外部能源事件立即触发一次功率重平衡，不再等待下一条AI建议获批。

运行储能回归测试和对照实验：

```text
python tools\virtual_greenhouse\test_energy_system.py
python tools\virtual_greenhouse\energy_storage_experiment.py
```

实验结果位于 `tools\virtual_greenhouse\energy_results\`，包含逐分钟 CSV、JSON 指标和 PNG 对照图。

当前版本采用可解释的规则 EMS 负责充放电：清洁能源优先、削峰、限电/停电保供和 SOC 保护。SAC V3 的动作维度保持不变，尚不直接输出电池功率；这样不会用新状态维度强行套用旧权重。未来若把 SOC、能源价格和电池寿命纳入 SAC，需要建立新状态、动作和奖励函数并重新训练、重新对照验收。

真实部署时，能源字段应分别由智能电表、光伏/风机逆变器、BMS 和 PCS 提供，控制命令通过对应协议适配器下发。本版本参数是工程仿真初值，不构成实际储能容量选型或 ROI 结论。
